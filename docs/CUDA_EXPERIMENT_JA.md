# CUDA / Auto 実験版

このworktreeのCUDA版は、既存のCPU/OpenMP版を置き換えません。配布物には次の2つの
DLLを別々に収録します。

- `koromo_cloth_solver.dll`: 従来のCPU/OpenMP実装
- `koromo_cloth_solver_cuda.dll`: CUDA実装

Blenderの計算バックエンドは `Auto`、`CPU`、`CUDA` から選べます。

## Autoの安全動作

`Auto` はCUDA DLL、NVIDIAデバイス、CUDAランタイムが利用できる場合だけCUDA DLLを
ロードします。どれかがなければCPU DLLを使います。さらに、現在の実測に基づいて次の
実行時フォールバックがあります。

- 8,192頂点未満は、GPU起動コストが大きいため最初からCPUで計算します。
- CUDAのPCGが設定された反復上限内に許容誤差へ到達しなければ、そのGPUフレームを
  採用せず、変更前の状態からCPUで再計算します。
- 一度CPUへ移ったソルバーは、残りのベイクもCPUで続行します。

GPUからCPUへ戻す場合、途中まで計算したGPU位置はホストへコミットしません。この動作を
検証する自動テストでは、CPU直接実行とAutoフォールバック後の全頂点位置が完全一致します。

明示的な `CUDA` は比較・ベンチマーク用です。小規模判定とPCG未収束時の自動CPU再計算を
無効にするため、通常のベイクにはまず `Auto` を使用してください。

## データ転送

衣服位置、速度、制約、BVH、PD/PCG作業配列はベイク中VRAMに常駐します。通常の
CPU/VRAM間転送は、フレームごとのアニメーションBODY頂点入力と、最終衣服位置・速度の
出力です。PCG前処理も制約グラフを色分けした対称スイープとしてGPU上で実行するため、
PCG反復ごとの全頂点往復はありません。

## RTX 5070 Tiでの初期実測

16,384頂点の収束する自由落下ケースでは、CPU約0.010秒、CUDA約0.0033秒で、位置差は
0でした。16,384衣服頂点と32,258 BODY三角形の接触ケースでは、CPU約0.084秒、CUDA
約0.029秒（約2.9倍）で、最大位置差は約0.00069 mでした。一方、強い縫合とひずみ制限に
よってPCG反復上限へ達する人工ケースでは、CUDA
単独の結果に差が出るため、AutoはCPUへ戻します。これは性能保証ではなく、Auto判定と
回帰テストのための初期測定です。実際の衣服・BODY・設定での継続計測が必要です。
